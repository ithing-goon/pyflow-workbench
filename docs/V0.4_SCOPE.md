# v0.4 계획: 비동기 실행의 실패 처리와 복구

상태: 계획. 아래 기능은 v0.3에 구현되어 있지 않다.

## 목표와 포함 범위

| 기능 | 범위 |
| --- | --- |
| Timeout | 노드별 제한 시간, async 취소와 하위 Subflow/Map 작업 정리 |
| Retry | 일반 실행 노드의 최대 시도 횟수, 대기 시간, 지수 백오프. 기본 재시도 없음 |
| Catch | 최종 실패를 오류 출력으로 전달하여 복구 분기 실행 |
| 추적 | 각 시도의 시작·종료·오류와 처리된 오류/미처리 실패 구분 |
| 편집기 | 정책 설정, 오류 분기 연결, JSON 저장·복원과 실행 예제 |

## 고정할 원칙

1. 재시도 대기 중에는 동시 실행 슬롯을 점유하지 않는다.
2. 이전 시도가 종료된 뒤에만 다음 시도를 시작한다. async 취소도 정리를 기다린다.
3. 동기 함수의 실행 중 타임아웃은 이번 범위에서 지원하지 않는다. 실행 thread를 강제 종료했다고 표시해서는 안 된다.
4. Retry는 명시적 opt-in이다. 외부 부작용의 exactly-once를 보장하지 않는다.
5. Subflow/Map 전체를 재시도하지 않는다. 성공한 자식 작업이 묵시적으로 다시 실행되지 않아야 한다.
6. Catch는 재시도가 모두 끝난 최종 실패를 받는다. 사용자/상위 실행 취소는 별도 처리하며 재시도나 Catch로 소비하지 않는다.
7. 오류 데이터는 원인 노드, 중첩 scope, 오류 종류, 메시지, 시도 횟수를 포함한다.
8. 기존 그래프에 정책이 없으면 v0.3 동작을 유지한다. null/비활성, 타입 검증, 공유 limiter와 결정적 순서를 보존한다.

## 구현 전 정할 세부 계약

다음은 합의된 구현 사실이 아니라 구현자가 설계·문서화·테스트해야 할 항목이다.

- Timeout의 기준: 슬롯 대기를 포함할지, 실행만 측정할지. 권장안은 일반 노드는 슬롯 획득 후 시도 단위로 측정하고 orchestrator는 자식 실행 기간을 측정하는 것이다.
- Subflow/Map 타임아웃 시 이미 시작된 동기 자식은 종료시킬 수 없다. 중단 가능 범위와 잔여 실행 상태를 정직하게 표현하고 재시도와 슬롯 재사용이 중첩 실행을 만들지 않게 한다.
- 취소를 억제하는 async 함수는 정확한 시간에 강제 종료할 수 없다. 제한 시간을 hard-kill 보장으로 설명하지 않는다.
- 재시도 가능 오류 분류와 최대 시도/백오프 상한. 그래프 검증 실패·취소는 재시도하지 않는다.
- 오류 출력 포트와 Catch 노드 표현, 정상/오류 경로의 활성 규칙, 일반 데이터 포트 이름과의 충돌 방지.
- 복구 성공 시 run 상태와 원래 실패 이력 보존. Catch가 연결됐다는 이유만으로 처리 성공으로 표시하지 않는다. 복구 분기 자체 실패는 미처리 실패로 남긴다.
- 중첩 오류 전파에서 동일 원인 중복 처리를 방지하는 규칙. v0.3의 '실패 노드가 하나라도 있으면 run 실패' 계약 변경을 명시한다.
- 최대 시도 횟수는 최초 실행을 포함하는지 명시한다. 권장 기본값은 총 1회다.

## 실행 순서

1. 실행 정책·시도·오류 모델과 검증/호환성 계약.
2. async Timeout과 취소 정리, 동기 작업 한계 처리.
3. 일반 노드 Retry와 백오프, 시도별 이벤트.
4. 최종 오류 분기/Catch와 run 결과 판정.
5. 프론트 정책·추적 UI, 저장/복원, 동작 예제.
6. 회귀/HTTP/build 검증과 문서 갱신.

## 완료 기준

- 일시 오류가 N번째 시도에서 성공하고, 시도 횟수·출력이 정확하다.
- 재시도 소진 후 Catch가 최종 오류를 한 번 받는다. 복구 성공과 실패가 구분된다.
- async Timeout 시 소유한 하위 작업을 취소·정리한다. 취소 중 추가 재시도가 시작되지 않는다.
- 동시성 1의 중첩 실행·재시도에서 교착이 없고, 백오프 중 독립 작업이 실행된다.
- 이전 시도와 다음 시도 실행이 겹치지 않으며 성공한 Map 아이템을 전체 재시도로 반복하지 않는다.
- 정책 없는 기존 그래프와 기존 81개 테스트를 유지한다.
- JSON round-trip, 편집기 검증, 시도별 스트리밍 이벤트를 테스트한다.
- 실제 HTTP 스트리밍으로 오류와 복구를 확인하고 TypeScript/Vite 빌드를 통과한다.
- 브라우저 확인 여부와 동기 thread의 제한을 결과에 명시한다.

## 제외 범위

스케줄러, 실행 이력 영구 저장, 재시작 복구, 외부 서비스 노드, Node-RED 호환 import/npm, 장기 메시지 스트림/루프, 프로세스 격리를 이번 증분에 포함하지 않는다.
